Validated decision

Prefer a bounded join with domain batch interfaces. Do not add a persistent point-leaf plan or a domain-aware executor. Each module combines inputs when it understands a physical or atomic reason to do so. Its existing loop then calls join_all_bounded over the resulting independent futures.

domain batch interface→ independent futures → join_all_bounded→ stable outputs → current policy owner→ complete leaf operation → ShardCoordinator

join_all_bounded polls in the caller's task, keeps at most N futures incomplete, admits and returns them in input order, and runs every supplied input. A waiting future keeps its position. The helper has no parking, replacement, terminal-outcome, or cleanup concepts.

TreeRouter owns path-batched descent. KeyResolver owns grouped logical resolution. NodeStore owns batch physical checks. KeyLocker owns per-leaf mutation groups, waits, rerouting, bookkeeping, and the sorted serial fallback. ShardCoordinator accepts one complete same-transaction operation for one exact path and combines compatible operations from different transactions.

Keep the existing scheduler yield and backend-I/O collection window in ShardCoordinator. Do not add a timed batching delay.
